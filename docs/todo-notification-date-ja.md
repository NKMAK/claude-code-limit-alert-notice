# TODO: 通知のリセット日付を英語から日本語表記にする

- ステータス: 未着手
- 作成日: 2026-06-21
- 関連: `usage-alert.sh`, `docs/decisions/0001-use-claude-usage-as-data-source.md`

## ゴール

Discord 通知に出るリセット時刻が英語表記なので、日本語表記にする。

- 現状: `リセット: Jun 21 at 7:29pm`
- 目標: `リセット: 6月21日 19:29`（24時間表記・日本語）

## 背景

リセット時刻は `claude -p "/usage"` の出力（例 `resets Jun 21 at 7:29pm (Asia/Tokyo)`）を
そのまま使っているため英語のまま。`usage-alert.sh` では括弧のタイムゾーンだけ落として
`sess_reset` として表示している（"Jun 21 at 7:29pm"）。

## 設計（案）

`usage-alert.sh` でリセット文字列を取り出した後、日本語・24時間表記へ整形する。

- 英語表記 `Jun 21 at 7:29pm` を `date` でパースして再フォーマットする案:
  ```sh
  # 例: BSD date(macOS) で 12h→24h・和文へ
  epoch=$(date -j -f "%b %d at %I:%M%p" "Jun 21 at 7:29pm" +%s 2>/dev/null)
  ja=$(date -r "$epoch" "+%-m月%-d日 %H:%M")   # → 6月21日 19:29
  ```
  - `%p`(am/pm) は小文字 `pm` を受けるか要検証。受けない場合は `tr 'a-z' 'A-Z'` で
    `PM` に正規化してから渡す。
  - `7pm`（分なし）のように分が無いケースの書式差にも対応する（`at %I%p` 等で再試行）。
  - **年が無い**ので `date` は当年扱いになる。年跨ぎ(12/31→1/1)で前年と誤解釈しないか確認。
- パース失敗時は**英語のままフォールバック**（誤表示・無言クラッシュを避ける）。

## 注意

- 週間リセット側は通知に出していない（現状は週間"使用率"のみ表示）。日付整形の対象は
  セッションのリセット時刻 `sess_reset` だけでよい。
- ロケール依存(`LC_TIME`)で `date` の月名解釈が変わりうる。パースは `LC_ALL=C` を付けて
  英語月名固定にすると安全。

## 受け入れ基準

- [ ] 通知のリセットが `6月21日 19:29` のような日本語・24時間表記になる
- [ ] `/usage` の実リセット時刻と一致する
- [ ] パース失敗時は英語表記のままで通知が壊れない
- [ ] 分なし(`7pm`)・年跨ぎでも破綻しない

## 検証コマンド

```sh
# 現在のリセット文字列（英語）
claude -p "/usage" --output-format json \
  | jq -r '.[]|select(.type=="result").result' | grep -i 'current session'

# 整形ロジックの単体確認
LC_ALL=C date -j -f "%b %d at %I:%M%p" "Jun 21 at 7:29PM" "+%-m月%-d日 %H:%M"
```
