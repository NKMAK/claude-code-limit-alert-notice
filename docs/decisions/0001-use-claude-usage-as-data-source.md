# 0001. 使用率の取得元を ccusage 近似から `claude -p "/usage"` に全面移行する

- ステータス: 採用
- 日付: 2026-06-21
- 関連: `usage-alert.sh`, `.env.example`, `install.sh`, `package.json`, `docs/article.md`
  / 削除: `calibrate.sh`, `ccusage` 依存

## 背景・問題

通知される使用率とリセット時刻が実態と大きくズレるという指摘があった。

1. **使用率がズレる**: 実際に `/usage` が 80% を示していても、本ツールは 57% と算出して
   80% 通知が発火しなかった。
2. **リセット時刻がズレる**: 通知は「リセットまで あと約3.3時間（21:00）」と出たが、
   実際のリセットは 19:29 だった。

### 旧方式とその限界

旧方式は **ccusage** で5hブロックの消費トークン (`totalTokens`) を集計し、
手動校正した `TOKEN_BUDGET` を分母に `% = totalTokens ÷ TOKEN_BUDGET × 100` で近似していた。
リセット時刻は ccusage の `blocks[0].endTime` を使っていた。問題点:

- **実上限はトークン数に正比例しない**。モデル種別(Opus/Sonnet)やキャッシュ比率で
  1トークンあたりの「重み」が変わるため、一度校正してもすぐズレる。恒久的に正確にできない。
- ccusage の `endTime` は「最初の利用時刻を正時に切り下げ + 5h」であり、Claude の
  サーバー側の実リセット（**分単位**・例 7:29pm）とは原理的に一致しない。
- 実リセット時刻は**ローカルのどこにも保存されていない**（JSONL ログの `rateLimits` は
  常に `null`、設定/テレメトリ/セッションにも無し）。ログだけからは正確に再現できない。

## 検討した選択肢

1. **TOKEN_BUDGET を再校正し続ける** — 近似のまま。根本解決にならず却下。
2. **OAuth トークンで Anthropic API を直叩き** — 正確だが、Keychain の認証情報アクセスが必要で
   サンドボックスにも「認証情報スキャン」としてブロックされる。非公開エンドポイント依存・
   トークンリフレッシュで壊れやすく、常駐ツールには不向き。却下。
3. **`claude -p "/usage" --output-format json` を使う** — 採用。

## 決定

データ源を **`claude -p "/usage" --output-format json`** に全面移行する。

- これは Claude Code 本体と同じ**サーバー側の正確な値**を返す:
  - セッション(5h)使用率
  - 実リセット時刻（分単位）
  - 週間(全モデル)使用率
- 呼び出しは `model: "<synthetic>"` / `total_cost_usd: 0` の**ローカル処理で課金トークンを
  消費しない**。
- `result` テキストを正規表現でパースして使用率・リセット時刻を取り出す。
- 通知済み判定の「ウィンドウ」キーはリセット時刻。ただし `/usage` 表示は分が ±1分ゆらぐ
  ことがある（7:30pm⇔7:29pm）ため、**判定キーは分を落として時(hour)単位に丸める**。
  表示は分まで正確なまま使う。

### 廃止したもの

- `TOKEN_BUDGET` 設定（残っていても無視）／キャリブレーション手順
- `calibrate.sh`
- `ccusage` 依存（`package.json` / `package-lock.json` / `node_modules`）

### 通知フォーマット

```
⚠️ Claude 5h使用量が 86% に到達
リセット: Jun 21 at 7:29pm
週(全モデル): 13%
```

## 結果・トレードオフ

- 使用率・リセット時刻が `/usage` と一致する正確な値になり、校正運用が不要になった。
  別PC/Web/API 併用分も含むアカウント単位の値になった（旧方式の過少カウントも解消）。
- 代償: **`claude` CLI のログインが必須**（未ログイン/認証切れ時は誤通知を避けて無言終了）。
- **`/usage` の出力テキスト書式に依存**してパースしているため、Claude Code の更新で書式が
  変わると拾えなくなる可能性がある（その場合も誤通知はせず無言終了する設計）。
- 通知タイミングは launchd 間隔（既定5分）ぶん遅延しうる。即時性は Stop フック併用で改善可能。
